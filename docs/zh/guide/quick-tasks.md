# 快捷任务

快捷任务用于从 Web 或 Telegram Bot 发起一次后台处理。它只提交任务，不在当前请求或 Telegram 更新处理线程中直接执行长时间工作。

## 入口与权限

### Web

登录后进入 **任务中心**（`/settings/scheduler`）。页面的“网页与 Telegram 快捷任务”卡片会列出当前已启用的 Telegram 菜单任务，每一项都可以直接点击 **立即执行**；其他允许无参数手动提交的任务仍在“临时任务”区域。页面也保留高频刷新任务链、低频维护任务链和 Telegram 快捷菜单的配置入口。

Web 任务接口是 `POST /api/tasks/run`。请求必须使用 JSON，并提交任务键；只有 Emby 管理员可以执行，普通用户会收到 `403`。

提交成功时 Web 返回 `202`，并通过 `x-etk-job-id` 提供 Job 编号；Telegram 则回复“任务已提交”。两者都应继续到任务中心查看最终结果。

### Telegram Bot

Telegram Bot 的快捷命令会显示在输入框左侧的 **Menu** 中。菜单由任务调度页的“Telegram 快捷菜单”配置，点击命令后由 Bot 提交对应任务。也可以使用 `/all_tasks` 查看可用任务按钮。

Telegram 快捷任务只接受已登记的管理员 Telegram ID。未登记的用户或聊天不会执行任务；把 Telegram ID 绑定到普通用户并不会授予任务执行权限。

Telegram Bot 在这里仅用于通知和快捷任务控制，不提供频道监听或 UserBot 资源采集入口。外部资源获取和订阅协作统一使用 MoviePilot，见[外部服务集成](/zh/guide/integrations)。

## 后台 Job、忙状态与排队

任务提交成功只表示 Job 已持久化，不代表任务已经开始或已经完成。请在任务中心查看 Job 的状态、进度、日志和最终结果。

- `queued`：已入队，等待 Worker 领取；
- `running`：Worker 正在执行；
- `retry_wait`：等待下一次重试；
- `cancel_requested`：已发出取消请求，任务会在下一个可取消检查点停止；
- `succeeded`、`failed`、`timed_out`、`cancelled`：终态。

Web 的“临时任务”采用忙状态保护：检测到已有活动 Job 时不会再次提交，页面通常提示“后台有任务正在运行，请稍后再试”（HTTP `409`）。请等待当前 Job 进入终态后再重试。

Telegram 快捷任务会通过持久化任务边界提交。已有 Job 时，新的 Telegram 任务可以先进入后台等待队列，因此 Bot 回复“任务已提交”仍不等于“正在执行”。重复点击会产生额外 Job；请以任务中心中的 Job 记录为准。

## 双模式任务

Web 手动执行以下任务时，会先选择处理模式：

| 任务键 | 快速模式（增量） | 深度模式（全量） |
| --- | --- | --- |
| `role-translation` | 跳过已处理项，处理需要补充或更新的角色名 | 面向全库重新处理角色名 |
| `enrich-aliases` | 按演员资料的冷却期和完整性处理过期项 | 忽略冷却期，处理所有需要补充资料的演员 |
| `populate-metadata` | 跳过已同步且未变化的项目 | 扫描全库并执行深度同步；任务自身仍可能跳过明确未变化的近期项目 |
| `restore_mediainfo` | 只检查并恢复 Emby 中缺失媒体流的实际版本 | 遍历全部在库版本并强制重建、注入媒体信息 |

任务链中的上述任务固定按增量参数执行。Telegram 快捷任务也不提供模式选择，按默认增量参数提交；需要深度模式时请从 Web 入口执行。

## 默认 Telegram 菜单的六项任务

首次配置或清空自定义菜单后，菜单回退到以下六项。任务名称可能随界面语言显示，但任务键和行为如下：

| 任务键 | 名称 | 实际行为 |
| --- | --- | --- |
| `task-chain-high-freq` | 高频刷新任务链 | 按已配置的高频任务序列依次执行子任务，适合白天的轻量刷新、追剧和订阅维护。序列为空时会跳过。 |
| `task-chain-low-freq` | 低频维护任务链 | 按已配置的低频任务序列依次执行资源占用较高的维护任务，适合夜间运行。序列为空时会跳过。 |
| `populate-metadata` | 同步媒体数据 | 将 Emby 媒体库基础数据同步到本地缓存，供追剧、订阅、整理和统计使用。默认是增量同步。 |
| `process-watchlist` | 刷新智能追剧 | 刷新智能追剧列表，检查连载剧更新并补充相关集的图片和元数据。 |
| `scan-cleanup-issues` | 扫描重复媒体 | 扫描重复媒体、异常文件和可清理项目，生成发现结果；扫描本身不等于立即删除文件。 |
| `system-auto-update` | 系统自动更新 | 当前结果为 **`SKIPPED`**。明文主线已禁用自动容器更新，不会自动拉取或替换 Docker 镜像；请使用受控的发布/升级流程。 |

菜单配置保存的是任务键。Telegram Bot 会在应用启动、开始轮询时重新注册 Bot 命令，所以保存后菜单没有立即变化时，需要重启应用（或容器）再检查。Telegram 的命令列表仍受 Bot 平台限制，建议只保留常用任务。

## 与资源获取的边界

快捷任务负责触发 ETKvNext 的本地任务链。外部资源搜索、订阅协作和转存完成事件只从 MoviePilot 进入；MoviePilot 转存完成后，ETKvNext 再继续本地 115 整理、元数据处理、Emby 入库和通知。

本地 115 的 `302` 直链播放、STRM 和虚拟库仍然可用，但它们属于本地存储与播放能力，不是共享资源中心、HDHive 或 Telegram 频道监听入口。
